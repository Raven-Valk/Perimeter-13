# Project 13 v6 in Wokwi (five tabs: Gateway + Modules A, B, C, D)

Five Wokwi projects, one per board. Each folder holds the three files for one project:

| Folder | Board | Parts in `diagram.json` |
|---|---|---|
| `Gateway` | ESP32 DevKit V1 | LCD, RFID reader, keypad, slide switch (tamper), 3 LEDs |
| `SensorModule_A` | ESP32 DevKitC | LCD, keypad, PIR **Z2** (GPIO 17, wall A–B) + PIR **Z1** (GPIO 19, wall A–D), slide switch (tamper), buzzer, 3 LEDs |
| `SensorModule_B` | ESP32 DevKitC | as A, with PIR **Z2** (GPIO 17) + PIR **Z3** (GPIO 19, wall B–C) |
| `SensorModule_C` | ESP32 DevKitC | LCD, keypad, PIR **Z3** (GPIO 17), one LED (GPIO 2). No buzzer, no tamper |
| `SensorModule_D` | ESP32 DevKitC | LCD, keypad, PIR **Z1** (GPIO 17), one LED (GPIO 2). No buzzer, no tamper |

`sketch.ino` is a single file (`link_protocol.h`, `mesh.h` and `secrets.h` are inside it) with `WOKWI_SIM 1`; the module sketches also have `BENCH_COMMANDS 1` and their own `MODULE_ID`. **Don't upload these to real boards** — use the firmware folders. They are generated by `Tools/make_wokwi.py`: change the firmware, run the script, paste again.

## Set up (about 10 minutes)

1. For each folder: wokwi.com → **New Project → ESP32**, paste `diagram.json` and `sketch.ino`, add `libraries.txt` (**▾ → New file…**), **Save** as "P13 Gateway", "P13 Module A" … "P13 Module D".
2. Open them in **separate browser windows**, tiled. Browsers slow down background tabs and links then time out (here: 8 s).
3. Press ▶ in all five. The first build takes about a minute; connecting 5–15 s.
4. Gateway LCD: `SYS DISARMED P0`, then pages `A:DIS B:DIS PC:N` / `C:DIS D:DIS M:OK`.
   Module Serial Monitors: `[sim] MQTT connected`, then `Gateway link UP`, `Module B link UP`, …

## Controls

| Where | Do | Means |
|---|---|---|
| Gateway | **RFID → Blue card → Tap**, keypad `1234#` | OPERATOR. Menu: 1 Arm, 2 Disarm, 3 Ack, 4 Maint, 5 Clear, 6 End, * log out |
| Gateway | **Green card**, `9876#` | MAINTENANCE. For 4/5/6 pick a target: 1–4 = A–D, 5 = all, 0 = gateway (clear only) |
| Module | **PIR → Simulate motion** | A: left PIR = Z2, right = Z1. B: left = Z2, right = Z3. C/D: the only PIR |
| Module | Serial Monitor: `arm`, `disarm`, `ack`, `clear`, `maint 30`, `end`, `status`, `log` | bench commands (act as the gateway, for this module only) |
| Module | Serial Monitor: `cut g 60` (or `cut a`, `cut c` …) | **relay test**: treat the direct link to that board as broken for 60 s; `cut g 0` ends it |
| Module | keypad `1234#` during an alarm | silence this module |
| A, B, gateway | **slide switch** right | lid opened (tamper) |

## Test script

Arm everything first: gateway, Blue card, `1234#`, **1** → "ARM OK, A:OK B:OK C:OK D:OK".

| # | Do | Expect |
|---|---|---|
| 1 Warning | D: PIR once | D: yellow-LED blink slow, "D-Z1 1/3". A: log "Motion seen by Module D", LCD "D-Z1 motion" |
| 2 Wall pair | within 20 s, A: right PIR (Z1) | **Intrusion zone 1** everywhere. **Only A's buzzer** sounds (zone 1 = wall A–D). B, C, D: "!! INTRUSION !!", no sound |
| 3 Escalation | C: PIR **once** | at once "Intrusion zone 3 (escalated)". **B's buzzer** joins (zone 3 = wall B–C). LCDs: "Zone 1+3" |
| 4 Acknowledge | gateway: Blue card, `1234#`, **3** | "ACK OK, A:OK B:OK C:OK D:OK", RECOVERY, then ARMED. Back to the normal rules |
| 5 Normal again | C: PIR once | only a warning ("C-Z3 1/3"), no alarm |
| 6 Corner | A: left PIR, then right PIR within 20 s | "Intrusion zone 1+2: A-Z2 + A-Z1 (corner)" |
| 7 Three hits | (after ack) D: PIR 3 times within 20 s | "Intrusion zone 1: D-Z1 x3" |
| 8 **Relay** | A: `cut c 60` | after ~6 s A logs "Module C: direct link lost, relayed through Gateway"; `status` shows `NET:*DgDD` … everything still works (try 1–2) |
| 9 Relay through a module | A: `cut g 60` | "Gateway: direct link lost, relayed through Module B" (or C/D); the gateway still gets A's status and logs |
| 10 Lost board | **Stop** D | ~8 s: "Module D link DOWN" on the others; zone 1 then confirms by A's 3-hit rule |
| 11 Tamper | A: slide switch right | "!! TAMPER P3 !!"; clear with `9876#` once the switch is back left |

## Differences from the real boards

- **Radio:** ESP-NOW becomes MQTT through a public broker (same signed packets): each board listens on `pinnacle13/p13-2d386efc/v6/to/<A|B|C|D|G>`. A relayed packet is published to the relay's topic and passed on to the receiver's.
- In Wokwi every board "hears" every other, so relaying only happens in a relay test (`cut`). On the real site it happens by itself when a wall or distance blocks one link.
- Timeouts: link 8 s (3 s real), direct link 6 s (2.5 s real). PIR warm-up 5 s (60 s real).
- Buzzer plays a 2 kHz tone. Nothing survives stopping Wokwi. No encryption and no MAC allow-list (MQTT has no MACs); signatures and replay protection are the same.
